# Codex Draw 完整实施方案

## 目标与交付范围

把原本围绕固定模型的图片调用 skill，扩展为按应用任务组织、可数据化扩展、可以验证交付的工作流。首版交付原生 CLI、12 个场景包、4 个模型别名配置、扩展协议、输出检查器、独立加密配置、迁移命令、跨平台发行包及 CI。

## 分层设计

1. Skill 入口负责需求澄清、场景选择、图片理解、能力边界及视觉验收；保持简洁，按需读取场景。
2. 场景层负责“做什么”：输入清单、提示词、验收清单、文章出处映射。没有硬编码模型名称。
3. 模型层负责“允许请求什么”：模型 ID、操作、格式、优先级、实验能力。配置是声明，不等于实测认证。
4. 执行层负责 JSON/multipart Images 协议、模型发现、有限重试、输出路径和错误处理。新协议需要显式代码适配。
5. 验证层负责文件解码、格式、尺寸、透明度和 GIF 元数据，并提示与请求的偏差。内容与审美由视觉复核完成。
6. 发布层负责版本、测试、二进制编译、白名单打包、校验和与 GitHub Release。

## 解耦与扩展原则

场景只引用任务需求，不引用具体模型。新增同协议模型或场景只增加数据文件；修改第三方模板须审阅提示词。使用 schema_version=1 和严格未知字段检查，避免拼错配置后悄悄忽略。

内置注册表适合开箱使用；持续维护的自定义场景应放外部完整注册表，通过 CODEX_DRAW_REGISTRY 选用。首版不做目录叠加与隐式覆盖；以后若增加多源注册表，需要明确优先级、冲突报错及来源追踪。

## 能力和降级

- 能力不匹配：发送请求前失败，给出缺失能力；不偷偷替换模型或输出格式。
- 模型列表不可用：兼容 Images 网关允许直接尝试注册候选，但结果仍由真实接口决定。
- GIF：服务商扩展必须显式放行；检查实际结果，不照抄请求参数。
- SVG：生成设计交接说明，真实生成报未实现；新增矢量协议、XML 安全检查后再提升能力。
- 透明背景、精确身份、圈外像素锁定：首版不承诺；实测与必要后处理作为独立阶段。
- UI、精灵图：交付视觉参考或动作画板，代码实现、切片与引擎集成独立处理。

## 补充的工程要求

**可追溯交付**：plan 的 JSON 包含提示词、模型、输入清单、输出路径、验收清单；draw 的 JSON 增加实际文件信息与偏差警告。用户可保存在项目内。不默认持久化个人提示词、图片或服务返回全文。

**费用与稳定性**：默认一次提交；超时不代表服务未执行。批任务共享模型发现，但每个任务独立处理错误；用户再明确决定是否重试。首版不实现账户余额查询或价格估算，因为各服务商计费不同。

**凭据与迁移**：新旧配置隔离、系统加密、用户在浏览器输入；旧配置导入由程序解密再加密，拒绝覆盖目标并保留原值。现有配置破损不自动改用环境变量。

**资产与授权**：原图与成图分开；拒绝默认覆盖。只发布合成测试数据，文章示例图片和用户素材不纳入仓库。涉及品牌或特定人物的内容按用户授权范围生成。

**测试**：单元测试验证注册表、未知字段、场景/模型扩展、离线计划、能力门控、GIF 帧解码、格式匹配和覆盖保护；mock 集成测试验证生成/编辑/批任务与配置页。Windows 测加密存储，Linux 测竞争条件。发布包检查包含技能入口与四个程序。

**发布与维护**：SemVer、变更日志、保留 MIT 署名；源码不提交二进制，Release 附压缩包与校验和。发布流水线通过后再把版本标成已交付。升级保留外部注册表与系统配置。
